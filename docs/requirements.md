# AnyKana 要件

## 1. MVV（2026-10-13 に固めた）

### Mission
打ちたい言葉の入力ソースへ、一発で直接届くようにする。

### Vision
言葉を行き来するたびの小さな引っかかり（今どれかを確かめる、何度も押す）が消えて、手が止まらない。AnyKana は、入れたことを忘れていられる道具になる。

### Value（上にあるものほど優先）

各 Value の1行目が価値。その下の「→」は、そこから決めたこと（決めたことを変えても、価値は変わらない）。2026-10-14 に、価値と決めたことを分けて書き直した。

1. 思ったとおりに: ふだんの使い方の中で、押したら一発で届き、押したつもりがないときは動かない
   - → キーと行き先は1対1。巡回させない
   - → 切り替えるのは、単独で押して離したときだけ（6章「⌘ だけを押して離したときに切り替える」）
   - → ふだんの順序から外れたとき（変換の途中で切り替えるなど）まで、仕組みを足して守ることはしない（2026-10-14）
2. シンプルに: やりたいことも、手段もシンプル。Karabiner-Elements のような重厚な道具にしない
   - → できるのは「キーを単独で押して離すと、その入力ソースへ」だけ
   - → 長押し・同時押し・時間の窓は使わない
3. 自分の手に合わせられる: どのキーでどの入力ソースへ行くかは、使う人が自分の感覚で決める。キーボードが変わっても置き直せる
   - → 変えられるのは、5つの枠の対応表だけ。設定はそれ以上増やさない
4. 意識に上らない: 入れたら忘れていられる。見せるもの・確認を増やさない
   - → メニューバーにも、できるだけ出さない（今の入力ソースは macOS の表示で足りる）
   - → 前のアプリから入力の届き先を奪わない。ウィンドウを出さず、macOS 自身の切り替え（⌃Space）で選ぶ（2026-10-15。その前は、一瞬出すウィンドウを透明にしていた）
5. 小さく、自分で持てる: 作り手が手を引いても使い続けられる大きさで作る
   - → 長く変わらない API の上に乗る

### 主な利用者
作り手自身。似た困りごとを持つ人が使うのは自由だが、そのための対応は目指さない。ソースだけを MIT ライセンスで公開し、ビルド済みのアプリは配らない。サポートはしない（2026-10-19）

## 2. なぜ作るか

- ⌘英かな（[iMasanari/cmd-eikana](https://github.com/iMasanari/cmd-eikana)）は、最後のリリースが 2017年6月、最後のコミットが 2021年1月で、保守は止まっている
- 配られている ⌘英かな（v2.2.3）は Intel 用（x86_64）で、Apple Silicon の上では Rosetta 2 を通して動く。Apple は、Rosetta を誰でも使えるのは macOS 27 までと発表している。OS を上げ続けると、いつか動かなくなる
- 手元でビルドして持てば、作り手が手を引いても使い続けられる。中心は小さく、長く変わっていない API の上に乗るので、抱えられる大きさ
- 左 ⌘ で英数・右 ⌘ でかな、は JIS キーボード（スペースの左が英数、右がかな）の配置を、US 配列で使えるようにするもの。⌘英かな と同じ

### 名前（2026-10-13）

AnyKana。響きが「英かな」とほぼ同じで、⌘英かな へのオマージュとリスペクトがありつつ、Any で上位互換の感じを出す。Kana は日本語の言葉で、日本語を読まない人には届かないので、何をする道具かは英語の一行（タグライン）と説明で伝える。タグラインは「Tap ⌘ to pick any input source.」。switch to だと to が重なり、トグルの響きもある。pick は「切り替えではなく、選ぶ」と合う。2026-10-19 に、暫定を外して決めた。⌥ と 🌐 も選べるようになったが、タグラインは主な使い方の ⌘ だけを言い、ほかは下の説明の一文（Picks any input source when you press ⌘, ⌥, or 🌐 alone.）が受け持つ。⌘英かな の行き先を探す人には、⌘ の記号が目印になる。抽象的な一行（One tap, any input source.）は、修飾キーを単独でタップするという違いが消え、ほかの切り替えのアプリにも当てはまるので取らなかった。⌘英かな も、キャッチコピーは持たず、名前（⌘ と 英かな）と説明の一文で伝えていた

- ディレクトリとリポジトリは `anykana`（小文字）、アプリの表示名・パッケージ・実行ファイルは `AnyKana`、Bundle ID は `io.github.takashi-w.anykana`、署名の証明書は `AnyKana Dev`

## 3. 何をするか

最初に考えた入力ソースは3つ:

| 入力ソース | ID |
| --- | --- |
| 英数（ABC） | `com.apple.keylayout.ABC` |
| かな（日本語・ローマ字入力） | `com.apple.inputmethod.Kotoeri.RomajiTyping.Japanese` |
| ボポモフォ（繁体中文・注音） | `com.apple.inputmethod.TCIM.Zhuyin` |

- 左 ⌘ を単独で押して離すと、英数にする
- 右 ⌘ を単独で押して離すと、かなにする
- 右 ⌥ を単独で押して離すと、ボポモフォにする（2026-10-14 に、一旦ここに置いた。下の「決めたこと」）
- キーを押している間にほかのキーを押したら（⌘C など）、何もしない
- 今どの入力ソースかに関係なく、押したキーで行き先が決まる（切り替えではなく、選ぶ）

### 押し方と行き先を、対応表で結ぶ

枠は5つ: 左 ⌘・右 ⌘・左 ⌥・右 ⌥・🌐。どれも単独で押して離すと、割り当てた行き先にする（下の「決めたこと」の「5つの枠に、一発で」）。最初は左右の ⌘ × 単押し・ダブルクリックの4通りで考えていた（2026-10-13）。

- 「どう押したか」と「どこへ行くか」は別のものとして分ける。押し方の判定は行き先を知らず、対応表は押し方の判定を知らない
- 行き先は2種類: キーを押したふりをする（英数 102、かな 104）か、入力ソースを ID で直接選ぶ
- 対応表は、使う人が置き直せるようにする（Value の「自分の手に合わせられる」）。アプリをもう一度開いたときだけ出る小さな画面で置き直す（6章の「決めたこと」）

## 4. やらないこと

enja-switcher にあって、要らないもの: CapsLock での切り替え、マウスのスクロールの反転、更新の確認。

## 5. 参考にするもの

- [toshi-kuji/enja-switcher](https://github.com/toshi-kuji/enja-switcher)（MIT）: 左右の ⌘ で英数とかなに切り替える。コードは取り込まず、ゼロから書いた。ハマりどころ（署名、止まったイベントタップの再開、二重起動、ログイン時の起動）の解き方は参考にした（2026-10-13）
- ⌘英かな: 乗り換えのもと。出発点にすぎない。動きは AnyKana の Value で決め、⌘英かな に合わせることは目的にしない（2026-10-13）

## 6. 決めたこと

### 対応表は、アプリをもう一度開いたときだけ出る小さな画面で置き直す（2026-10-19）

割り当てを置き直したり、入力ソースを足したりする場面はありうる（例: ボポモフォを 🌐 に移す）。メニューバー、設定の画面、コマンドラインを比べて決めた。

- 動いている AnyKana をもう一度開いたとき（Spotlight や Finder から）だけ、小さな画面を出す。ふだんは何も見せない（Value 4「意識に上らない」）。メニューバーにアイコンを置くと、たまにしか使わない置き直しのために、いつも見えていることになる
- 行き先は、今有効な入力ソースの一覧から選ぶ。ID を調べて書かなくてよい（Value 3「自分の手に合わせられる」）。コマンドラインや設定のファイルは小さいが、ID を書くことになる
- 対応表は UserDefaults に「枠の名前 → 入力ソースの ID」の形で残す。`defaults write` でも書き換えられるので、コマンドラインの道は作らなくても残る
- 行き先に ABC を選ぶと英数のキー（102）を、日本語（ローマ字入力）を選ぶとかなのキー（104）を送る。ほかは ID で選ぶ（下の「API で選んでから ⌃Space で戻す」）。それまでの動きを変えないため
- 終了も、この画面に置く。それまでは `pkill -x AnyKana` しかなかった
- 🌐 に割り当てたら、macOS の「🌐 キーを押して」を「何もしない」に変える必要があると、画面に一言出す。設定を読んだり書き換えたりする仕組みは足さない（Value 2「シンプルに」）
- AnyKana が動いていないときに開くと、画面は出さずに動き始めるだけ。ログイン時の起動と見分ける仕組みは足さない（Value 2）。もう一度開けば出る
- 割り当てていた入力ソースをシステム設定で外したら、ポップアップにはその ID を「（入っていない）」と付けて出す。黙って「なし」に見せると、外したことに気づけない

UI 案（未確定。2026-10-19 に2回見直した）:

- 5つの枠を、左 ⌘・右 ⌘・左 ⌥・右 ⌥・🌐 の順で1行ずつ並べ、それぞれにポップアップ（「なし」と、有効な入力ソースの名前）を置く。キーボードのいちばん下の段の順（🌐・左 ⌥・左 ⌘・右 ⌘・右 ⌥）も試したが、左右が入り交じって散らばって見える
- 枠の名前は、キーをキーボードの刻印のように枠で囲み、後ろに左右を添える。キーを先に置いて縦にそろえる。「単独で押して離すと」のような説明の文は置かず、1つのキーを押すことを形で伝える（説明の文は、分かりにくく、くどくなる）
- 画面の言語は、システムの言語に従う（英語と日本語を用意し、macOS がアプリごとに選ぶ。アプリだけ変えたければ、システム設定の「言語と地域」→「アプリケーション」）。入力ソースの名前も、同じ言語で macOS がくれるもの（入力メニューと同じ）をそのまま出し、AnyKana で付け直さない。入力ソースを選ばせる Mac のアプリは、たいていそうしている。最初はアプリが言語を名乗っておらず、日本語の文言に英語の名前（Hiragana）が混ざっていた。日本語に固定してみたが、システムの言語が英語の Mac では、メニューバーとそろうのは英語の名前の方だった
- 「完了」のボタンは置かない。macOS の設定の窓は、選んだ時点で効き、閉じれば終わる
- 終了は、割り当てとは別の節に、ボタン1つで置く。最初は窓の右下に置いたが、そこは macOS でも Material でも完了や確定のボタンの位置なので、設定を終えるボタンと読み違えやすい
- メニューのないアプリなので、⌘W と esc で閉じられるよう、窓が自分で受ける
- 🌐 に割り当てたら、枠の下に一言出し、その中の「キーボードの設定」をリンクにする（開くだけで、読み書きはしない）

### ID で選ぶ入力ソースは、API で選んでから ⌃Space で戻す（2026-10-15）

一瞬ウィンドウを出すやり方（下）を、これに差し替えた。API（`TISSelectInputSource`）で目的の入力ソースを選び、次に ABC を選んでから、⌃Space（macOS の「前の入力ソースを選択」）を送る。API で選んだものも「直前に使った」に残るので、macOS 自身の切り替えで目的に戻り、入力も本当に変わる。ウィンドウを出さないので、前のアプリから入力の届き先を奪わない。spike（`zhuyin-probe`）で確かめた結果:

| 打つアプリ | 始める前 | やり方 | 結果 |
| --- | --- | --- | --- |
| テキストエディット | 英数 | prev（API で選んで ⌃Space で戻る） | ✔ ボポモフォになる。Spotlight を開いていても閉じない。チカっとせず、カーソルが入力欄に残ったまま |
| テキストエディット | 英数 | next:1（⌃⌥Space、入力メニューの次のソース） | ✘ かなになった（メニューの順で固定という見込みが外れた） |

- ⌃Space の「前の入力ソースを選択」が、システム設定（キーボード → キーボードショートカット → 入力ソース）でオンになっていて、⌃Space のままであることに頼る。変えると、表示だけ変わって入力は前のままになる。設定を読んで合わせる仕組みは足さない（Value 2「シンプルに」。設定を読む公開の API はない）
- キーを送るので、アクセシビリティの権限が要る。英数とかなのキーを送るのと同じ権限なので、足さなくてよい
- 間にはさむのは ABC。ABC そのものを ID で選ぶことはない（英数はキー 102 を送る）
- 一瞬 ABC を通る（あわせて 0.1 秒ほど）。メニューバーの入力ソースの表示を見ていると、忙しく動くのが分かるが、問題ない。カーソルだけを見ていれば、自然に切り替わる（2026-10-15）
- 変換の途中で切り替えると、前と同じく、打っていた文字は確定されずに消える。2026-10-14 の判断（下）のまま、このままにする（2026-10-15 に確かめた）
- 確かめたのは macOS 14.7（Sonoma）。macOS 26.5（Tahoe）でも効く（2026-10-19、割り当ての画面の確かめで 🌐 → 注音）
- 右 ⌥ のあと、あえてだいぶ急いで打つと、最初の数文字が ABC やかなで入ることがある（ㄋu、ｓu など）。普通のペースなら起きないので、待ち時間を詰める仕組みは足さない（Value 1 の「ふだんの使い方の中で」。2026-10-15 に確かめた）

### ID で選ぶ入力ソースは、選んだあとに小さなウィンドウを一瞬出す（2026-10-13。2026-10-15 に上のやり方へ差し替えた）

入力ソースの API（`TISSelectInputSource`）で注音を選ぶと、メニューバーの表示は「注」に変わるが、入力は前のまま（`su` と打つと `su`）。知られている不具合が、そのまま出た。

macism（laishulu/macism）と同じく、選んだあとに、タイトルバー付きの小さなウィンドウを一瞬出して元のアプリへ戻すと、入力も変わった。spike（`zhuyin-probe`）では、テキストエディット・Chrome・Slack で効き、出す時間は 10 ms でも効いた（macOS 14.7）。

- ウィンドウは、キー入力を受けるウィンドウ（キーウィンドウ）になれる必要がある。枠なし（`.borderless`）では効かない。透明（`alphaValue = 0`）でも効く
- 副作用があった（2026-10-14）: 一瞬だけ前のアプリから入力の届き先を奪うので、Spotlight が閉じ、Chrome やターミナルの入力欄がチカっとする。かなで変換している途中なら、候補が閉じて、打っていた文字は確定されずに消える
- 入力の届き先を奪うことが Value 4「意識に上らない」とぶつかるので、上の ⌃Space で戻すやり方に差し替えた
- 変換の途中の文字が消えるのは、差し替えたあとも変わらない。日本語で確定してから切り替えればよいので、英数キーを先に送って確定させる仕組みは入れない（2026-10-14）

### ⌘ だけを押して離したときに切り替える（2026-10-13）

⌘ を押してから離すまでに、⌘ 以外のことが何か起きたら、切り替えない。⌘ より前に押されていた修飾キーも、順番によらず同じに扱う。

| 場面 | ⌘英かな（確かめた） | AnyKana |
| --- | --- | --- |
| ⌘ を押したままクリック（Chrome で新しいタブに開く） | 切り替えない | 切り替えない |
| ⌘ を押したまま Shift | 切り替えない | 切り替えない |
| Shift を押したまま ⌘ をタップ | 切り替える | **切り替えない** |
| 左右の ⌘ を両方 | （未確認） | 切り替えない |
| ⌘ を押したままスクロール（Figma や地図で拡大する） | （未確認） | 切り替えない（2026-10-13 に足した） |

- Shift → ⌘ だけ ⌘英かな と変えた。⌘英かな は「⌘ を押したあとに起きたこと」しか見ないので、前から押されていた Shift を見落とす。「⌘ だけを押して離したとき」と一言で言える決まりの方を取った。Shift を押したまま ⌘ をタップすることはふだんほぼないので、乗り換えても困らない
- 長く押していても、ほかに何も起きなければ切り替える（⌘英かな と同じ。押している時間では区切らない）。時間で区切ると、どこまでが単押しかが手に分からず、かえって思ったとおりに動かない。⌘ を押したまま考え直して離したときにも切り替わるのは、Value 1 の「押したつもりがないときは動かない」と少しぶつかるが、こちらを取る（2026-10-13）
- 切り替えるのは、押した瞬間ではなく、離した瞬間（⌘英かな と同じ。誤って切り替わるのを減らす方を取る）。押した時点では単独のタップか ⌘C の ⌘ かを区別できないので、押した瞬間にすると、ショートカットのたびに切り替えて戻すことになる。離すまで次の文字は打てない（押したまま打つとショートカットになる）ので、離した瞬間でも最初の1文字には間に合う
- CapsLock は修飾キーとして数えない（オンのあいだずっと立っている印なので、数えると切り替えられなくなる）

### 5つの枠に、一発で（2026-10-13）

3つ目からの入力ソースは、⌘ のダブルクリックではなく、別のキーを単独で押して離して選ぶ。枠は、左右の ⌘、左右の ⌥、🌐 の5つ。多くの言語を使う人でも足りる。

- 困っているのは、ほしい入力ソースに一発で届かないこと。Control + Space や 🌐 の巡回は、今どれかを覚えていないと目的に着かない。たとえば 🌐 の巡回で注音に着くには、今どれかを見ながら何度か押すことになる
- ダブルクリックをやめたのは、2回押す・0.3 秒の窓を待つ・1回目で英数やかなを通ってから変わる、の3つがあるから。念のため ⌘ を2回押す癖があると、意図せず飛ぶ
- 長押しと、複数のキーの同時押しは使わない。押し方を覚える手間が増え、判定にも時間の窓が要る（Value 2）
- ⌥ も ⌘ と同じ決まり（単独で押して離したとき）。⌥ を単独で押して離すことは、macOS ではふだん意味を持たない
- 🌐 は、macOS の「🌐 キーを押して: 入力ソースを変更」に使われていることが多い。AnyKana で使うなら、ここを「何もしない」に変える（そのままだと、macOS の巡回と二重に動く）。小指で届き、ほかの用途とぶつかりにくい
- 確かめたキーボードは、内蔵の US 配列（ANSI）。右側に ⌘ と ⌥ が並ぶ
- 最初の割り当てでは、ボポモフォを右 ⌥ に置き、左 ⌥ と 🌐 は空けておく（2026-10-14）。そのため、最初は macOS の「🌐 キーを押して」を変えなくてよい。🌐 に割り当てるときは変える（上の「対応表は、アプリをもう一度開いたときだけ出る小さな画面で置き直す」）

## 7. 決めていないこと

- アイコン（仮置き）を作り直すか
